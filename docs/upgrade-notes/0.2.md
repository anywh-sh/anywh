**Update the relay and the app together.** The connection protocol between
them changed (version 1 → 3), and each side now refuses the other instead of
misreading it: a 0.2 app connected to a 0.1 relay says the relay needs an
update, and the other way round. The in-app updater only updates the app, so
update the relay too:

- Linux: `curl -fsSL https://anywh.sh/install | sh -s -- --relay-only`
- macOS: `brew upgrade anywh-relay`

**A new service per profile: the agent host.** Rooms run their agents in
`anywh-agent-host@<profile>`, a systemd user service next to
`anywh-relay@<profile>`, so they keep running across a relay restart. The
installer above sets it up. If you manage the units yourself, re-run
`infra/systemd/install.sh` and then `infra/systemd/add-profile.sh` for each
profile, or enable it directly with
`systemctl --user enable --now anywh-agent-host@<profile>`. Without it the
relay and ordinary chats keep working; rooms don't.

**On macOS, rooms are not available yet.** The Homebrew relay doesn't ship an
agent host, so it doesn't connect to one. Ordinary chats work as before.

**Session files are migrated on first start, with no way back.** The 0.2
relay rewrites `sessions.json` into its new per-agent shape the first time
it loads it; every session keeps its title, folder, model and permission
mode. A 0.1 relay misreads the migrated file (it lists the titles but can't
resume the conversations), so to downgrade, restore a copy taken before
upgrading.

**Development builds use their own identifier.** A build from source now
installs as `dev.anywh.local`, with its own data directory, so it no longer
shares profiles with the installed app. Official releases are unchanged
(`sh.anywh.client`).
